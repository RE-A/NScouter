# 작업 공간(판) 설계 — 원본 스카우터의 흐름으로

> 상태: **설계안 (구현 전)** · 2026-11-17 · 개정: 트리 따라감/고정 · 대시보드 프리셋 · XLog N개 · 점 예산 · 결정 반영(콜렉터 트리·단축키·원본 화면·예산 100만), 제안(Visualize·통계 자리·도킹 라이브러리)
> 근거: 사용자 피드백(원본과 사용성이 달라 적응이 힘들다 · 글자가 작다 · 여러 XLog 를 한 화면에) 과
> 원본 클라이언트 소스 `scouter-project/scouter` `scouter.client` (커밋 `14dcf26`).

---

## 1. 왜 바꾸나

피드백의 뿌리는 화면 하나하나가 아니라 **구조 차이**다.

| | 원본 스카우터 | 지금 NScouter |
|---|---|---|
| 화면의 대상 | **화면마다** 콜렉터×종류(또는 에이전트 하나)가 박힌다 | 왼쪽 목록 하나를 모든 화면이 같이 쓴다 (XLog 만 탭마다) |
| 화면 여는 길 | Objects 트리 **오른쪽 클릭 → 메뉴** | 위쪽 탭(XLog/Active/Visualize/Counter/Alert/통계) |
| 한 화면에 | XLog·EQ·카운터·Alert 를 끌어 붙여 **동시에** | 탭 하나씩. XLog 끼리만 4판 |
| 시작 화면 | 짜인 대시보드 (왼쪽 열·카운터 4개·XLog) | XLog 탭 하나 |

탭이 나뉜 것은 «대상을 화면 전체가 하나로 공유한다» 는 데이터 구조의 결과다. 그래서 판 나누기만 넓혀서는
안 되고, **화면이 저마다 대상을 갖게** 하는 것이 먼저다. XLog 는 이미 탭마다 서버를 고르므로 절반 와 있다.

## 2. 원본에서 화면을 여는 과정 (소스로 확인한 것)

1. **기본 배치** (`PerspectiveService.java`) — 왼쪽 열 Objects / Alert / Active Service EQ / Host CPU,
   가운데 열 Recent User · TPS · Elapsed Time · Heap Used, 오른쪽 XLog. 기본 호스트·WAS 종류는 설정값.
2. **Objects 트리** — `콜렉터 → 오브젝트 종류 → 에이전트`.
3. **오른쪽 클릭 메뉴** (`ObjectNavigationView.fillMenu`, `MenuUtil`)
   - 콜렉터: 종류별 하위 메뉴 — 그 종류의 카운터 전부 + 특수 메뉴(Heap Memory, EQ, Vertical EQ,
     Active Service List, Active Speed, **XLog**, Service Count, Service Group TPS/Elapsed, Unique Visitor,
     Summary, File Descriptor). 그 밖에 Total Summary, Alert Detail List, 설정
   - 종류: 그 종류의 카운터 목록
   - 에이전트: Performance Counter(그 에이전트 하나), Performance Snapshot(Thread List, Active Service List,
     Class List, Heap Histogram, Thread Dump, Env, Socket, GC …), Stack Analyzer, Configure, 색, Properties
4. **대상이 박힌 화면** — 화면 ID 에 `콜렉터ID&종류` 를 붙여 연다. 같은 대상이면 있던 화면이 앞으로,
   다르면 새 화면. 제목 `XLog - PRD-FSCPS`, 부제 `ⓢCJFW | PRD-FSCPS's XLog Realtime`.
5. **배치** — 새 화면은 정해진 자리에 뜨고, 제목 탭을 끌어 붙인다. 배치는 작업 공간에 남는다.
6. **좁히기** — 트리에서 에이전트를 더블클릭하면 그 에이전트만 남기는 **전역 필터**(트리 배경 하늘색).
   XLog·EQ·카운터가 모두 따른다. 다시 더블클릭 또는 `Clear Object Filter` 로 푼다.
7. **키** — 전역 단축키는 없다(`org.eclipse.ui.bindings` 가 비어 있다). XLog 차트 안에서만
   (`XLogViewPainter.keyPressed`): `↑`/`↓` Y축 최대(2초 이상이면 1초, 아래면 0.1초씩),
   `+`/`-` 시간 폭 1분씩, `←`/`→` 시간 10초씩 이동. 프로파일 창 `f` 찾기.

## 3. 원칙

**원본의 흐름을 뼈대로, 지금 앱이 고친 것은 그 위에 남긴다.**

| 원본에서 가져온다 | 지금 앱에서 남긴다 (원본보다 나은 것) |
|---|---|
| 트리 오른쪽 클릭으로 화면을 연다 | 서비스 묶기(ECS Task 를 서비스로) · 그룹 규칙 |
| 화면마다 대상을 박을 수 있다(고정 판) | 왼쪽 트리로 고르기 — 판은 기본으로 트리를 따라간다 · 여러 콜렉터를 함께 붙이기(`hub`) |
| 끌어 붙이는 배치, 배치 저장 | 화면마다 실시간/과거·구간·거름 조건(지금 XLog 탭) |
| 원본과 같은 기본 배치 | 트랜잭션 찾기 · 통계 · 프로파일 검색 · 저장본 |
| 에이전트 더블클릭 = 그것만 보기 · 퍼스펙티브(대시보드 프리셋) | 새 창으로 떼기(모니터 여러 대) |
| XLog 키 `↑↓ +- ←→` | 지금 단축키(`Ctrl+F`, `F5`, `Ctrl+R` …) — 겹치면 원본 쪽 |
| 흰 바탕 · 읽히는 글자 | 보이는 판만 데이터를 받는다 |

## 4. 핵심 개념 — 판(Panel)

```ts
interface Panel {
  id: string;            // 바뀌지 않는다
  kind: PanelKind;       // 무엇을 그리나
  target: Target;        // 무엇을 보나 — 판마다
  view?: PanelView;      // 판마다의 조건 (XLog: 모드·구간·차트 설정·거름 = 지금 XLogTab 의 나머지)
  title?: string;        // 사람이 붙인 이름. 없으면 kind + target 에서 만든다
}

type Target =
  | { by: 'linked' }                                        // 왼쪽 트리를 따라간다 — 기본값
  | { by: 'type'; collector: string; objType: string }      // 원본의 기본 단위
  | { by: 'selection'; selection: GroupSelection }          // 지금 앱의 고르기(서비스 묶음·낱개 Task)
  | { by: 'agent'; collector: string; objName: string };    // 에이전트 하나 (이름으로 — 해시는 갈린다)
```

- `selection` 은 지금 `XLogTab.selection` 그대로다 — 이름으로 들고 해시는 명단이 바뀔 때마다 푼다
  (`groupSelection.ts`). `type`·`agent` 도 같은 방식으로 푼다.
- 콜렉터는 이름으로 든다. 하나만 붙어 있으면 화면에 드러내지 않는다.

### 트리 따라감(🔗) 과 고정(📌)

왼쪽 트리는 **그대로 둔다.** 원본에서 트리 선택은 모든 화면에 걸리는 전역 필터(`ObjectSelectManager`)였다 —
지금 트리가 하는 일과 같다. 그래서 판은 기본으로 트리를 따라가고, 원본처럼 대상별 화면이 필요할 때만 고정한다.

- **따라감 판(`linked`)** — 트리에서 고른 것을 본다. 기본 대시보드의 판은 전부 따라감이다 —
  트리에서 서비스를 고르면 XLog·EQ·카운터·CPU 가 **한꺼번에** 그 서비스로 바뀐다. 지금의 손버릇 그대로,
  다만 한 화면에 다 보인다. 지금 «Active·Counter 는 지금 XLog 탭의 선택을 따른다» 를 모든 판으로 넓힌 것이다.
- **고정 판(`type`·`selection`·`agent`)** — 트리를 무시한다. 트리 오른쪽 클릭 `XLog 열기` 로 열리는 판
  (원본의 `XLog - PRD-FSCPS`). PRD 와 QA 를 나란히 볼 때 쓴다. 지금 «XLog 탭마다 서버 고르기» 를 넓힌 것이다.
- ~~트리는 늘 «따라감 선택» 하나만 고친다.~~ **구현에서 바꿨다(P1-2):** 트리는 **지금 판**의 선택을 보여 주고 고친다 —
  지금 판이 따라감이면 따라감 판 **전부**가, 고정이면 그 판만 바뀐다. 처음 규칙대로면 고정 판을 눌러도 트리가 그 판의
  서버를 안 보여 주고, 고정 판의 대상을 바꾸려면 따로 고르기 창이 있어야 했다. 지금 손버릇(판을 누르고 트리로 고른다)을
  살리고, 어느 판을 고치는지는 판 머리 🔗/📌 와 지금 판 강조선으로 드러낸다.
- 고정 판의 대상을 바꾸는 길: 판 머리 `📌` 메뉴 → `지금 트리 선택으로 고정` · `따라감으로 풀기` ·
  `대상 고르기`(트리와 같은 목록을 작게 띄운다), 또는 트리 오른쪽 클릭 `이 대상으로 … 열기`.
- 판 머리에 지금 대상을 늘 적는다: `🔗 결제 서비스` / `📌 QA-SAFS` (원본의 부제 자리).

### PanelKind (1차)

| kind | 지금 컴포넌트 | 원본 대응 |
|---|---|---|
| `xlog` | `XLogChart` + 툴바 | XLog Realtime |
| `counter` (카운터 이름) | `CounterChart` | Counter RealTime All/Total |
| `eq` | `ActiveServicePanel` | Active Service EQ |
| `activeList` | `ActiveTab` 목록 | Active Service List |
| `alert` | `AlertFullView` | Alert |
| `summary` | `SummaryPanel` | Summary |
| `serviceGroup` | `ServiceGroupPanel` | Service Group TPS/Elapsed |
| `topology` | `TopologyPanel` | (원본 없음) |
| `fiveMin` | `FiveMinCounterChart` | Today/Past 카운터 |

`Objects 트리` 는 판이 아니라 왼쪽에 고정한다(원본도 닫을 수 없다).

## 5. 배치 — 도킹

- **배치 = 나눔(가로/세로, 몫) 과 판 묶음(탭 여러 개) 의 나무.** 판 묶음 안에서는 탭으로 오간다.
- 판 제목 탭을 끌어 다른 판의 **가장자리**에 놓으면 그 옆에 서고, **가운데**에 놓으면 그 묶음의 탭이 된다.
  지금 `XLogSplit` 의 손버릇(`dropSideAt`, 가장자리 1/4) 을 그대로 넓힌다.
- 판 수 제한: 지금 4(탭 6) → **16**. 판이 엽서만 해지는 것은 사용자가 정할 일이다.
- **`격자로 정렬`** — XLog 판을 판 수에 맞게 고르게 다시 나눈다(3개 3열, 4개 2×2, 6개 3×2, 9개 3×3 …).
- 판이 좁아지면 툴바를 접고 판 머리에 대상 이름과 건수만 남긴다.
- **창 밖으로 끌면 새 창** — 지금 XLog 떼기(`detached/`)를 모든 판으로 넓힌다. 창마다 배치 나무를 한 벌 든다.
- 배치는 `config.json` 에 남긴다(지금 `xlog_tabs` · `xlog_split` · `xlog_windows` 를 대신한다).
- **도킹은 라이브러리로 — `dockview-react` 제안** (확인 대기 · Q3). 패키지를 받아 형식 정의를 읽어 확인한 것:

  | | `dockview-react` 8.9.0 | `flexlayout-react` 0.11.2 | 직접 넓히기(`XLogSplit`) |
  |---|---|---|---|
  | 라이선스 · 의존성 | MIT · `dockview-core` 하나 | MIT · 없음 | — |
  | React 19 · 형식 | 됨 · `.d.ts` 있음 | 됨 · `.d.ts` 있음 | — |
  | 옮겨도 다시 세우지 않기 | `renderer: 'always'` — 숨거나 옮겨도 판 DOM 을 살려 둔다 | `enableRenderOnDemand` 를 끄면 | 지금 방식(자리만 바꿈) |
  | 배치 저장 | `toJSON` / `fromJSON` | `toJson` / `fromJson` | 직접 |
  | 테마 | CSS 변수(`--dv-*`) — 토큰에 이어 붙인다 | CSS 클래스 | 토큰 그대로 |
  | 떠 있는 판 · 새 창 | 떠 있는 묶음 · 팝아웃(`window.open`) | 팝아웃 | 지금 Tauri 창 떼기 |
  | 최근 배포 | 2026-11-08 | 2026-11-16 | — |

  - `dockview` 를 고른 까닭: 판을 살려 둔 채 옮기는 것이 옵션 하나이고(차트가 받아 둔 점을 잃지 않는다), 테마가
    CSS 변수라 흰/어두운 테마 토큰에 바로 물린다. 판 묶음·떠 있는 판·나눔이 원본 Eclipse 의 손버릇과 가깝다.
  - **새 창은 라이브러리 팝아웃을 쓰지 않는다.** 팝아웃은 `window.open` 으로 연 창에 DOM 을 옮기는 방식이라
    Tauri(WebView2) 에서 되는지 확인하지 않았고, 지금 «창마다 App 한 벌» 구조(`detached/`)와 다르다.
    창마다 dockview 를 하나씩 두고, 창 사이 옮기기는 지금처럼 «창 밖으로 끌면 새 Tauri 창» 으로 한다.
  - P1 첫 일: dockview 로 XLog 판 둘을 띄워 ① 옮겨도 점이 남나 ② 창 밖 끌기를 잡을 수 있나 ③ 16판 렌더 비용
    ④ 테마 토큰 연결 — 넷을 확인하고 확정한다. 안 되면 `flexlayout-react`, 그다음 직접 넓히기.
  - **확인 결과 (2026-11-17, `dockview-react` 8.9.0, 브라우저에서 실제 XLog 렌더러로)** — 채택.
    ① `defaultRenderer="always"`: 판을 다른 묶음 뒤로 넣고 빼고, 마우스로 끌어 옮겨도 판이 한 번만 만들어지고
       받아 둔 점이 이어진다 ② `dndStrategy="html5"`: 탭을 끌면 `onWillDragPanel`(DragEvent) 과 문서의 `dragend`(좌표) 가
       온다 — 지금 탭 줄의 «창 밖이면 새 창» 감지(`XLogTabBar`)를 그대로 붙일 수 있다. **창 밖(Tauri) 은 붙인 뒤 앱에서 확인**
       ③ 판 16개·판마다 점 5천을 매 프레임 그려도 판마다 59.5fps ④ `dockview-theme-light dockview-theme-ns`
       (`src/styles/dockview-theme.css`) 로 라이트·다크 모두 토큰을 따른다.
    - 발견: 판이 아주 작으면 XLog 머리 글자(`dots`·`Elapsed`)와 축 글자가 겹친다 — 좁은 판에서는 줄이거나 숨긴다(P1).

## 6. 여는 길

1. **트리 오른쪽 클릭** — 원본 메뉴 구성을 따른다.

   | 누른 곳 | 메뉴 | 여는 판의 대상 |
   |---|---|---|
   | 콜렉터 | 종류별 하위 메뉴: 카운터들 · XLog · EQ · Active List · Summary · Service Group … / Alert | `type` |
   | 종류 · 서비스 묶음 | 카운터들 · XLog · EQ · Active List · Summary | `type` 또는 `selection` |
   | 에이전트 | 그 에이전트의 카운터들 · XLog · 스냅샷(Thread/Active/Class/Heap/Env/Socket…) · 설정 | `agent` |

   «서비스 묶음» 은 지금 앱의 묶기(서비스로 묶어 보기)일 때 나오는 노드다 — 원본에 없는 단위지만 같은 메뉴를 준다.
2. **같은 대상·같은 종류면 있던 판을 앞으로** — 원본과 같다. `Shift` 를 누르고 고르면 새 판.
3. **판 머리 메뉴** — 대상 바꾸기(트리에서 고른 것으로), 이름 바꾸기, 복제(지금 `+ 탭`), 새 창으로, 닫기.
4. **판이 없을 때 트리에서 끌어 놓기** — 종류·묶음·에이전트를 판 위로 끌면 그 대상의 XLog 판(기본).

### XLog 를 N 개 띄우기

| 방법 | 쓰임 |
|---|---|
| 트리에서 서비스 여럿 고르고 오른쪽 클릭 → `각각 XLog 로 열기` | 서비스 N 개를 한 번에 N 판(고정)으로, **격자로 자동 정렬** |
| 트리에서 하나 오른쪽 클릭 → `XLog 열기` | 원본과 같다. 같은 대상이면 있던 판이 앞으로, `Shift` 면 새 판 |
| 판 머리 → `복제` | 같은 대상·다른 조건 — 실시간 vs 어제 같은 시각, 전체 vs 에러만 |
| 판 머리 → `+ XLog` | 빈 판(따라감)을 옆에 |

- 같은 대상·같은 조건의 판이 둘이면(따라감 판 둘 등) «같은 내용» 이라 알리고 `고정으로 바꾸기` 를 권한다.
- 점 보관은 10장의 앱 전체 예산을 나눠 쓴다.

## 7. 에이전트 더블클릭

- 원본의 «더블클릭 = 전역 필터» 는 트리 따라감(4장)이 그 일을 하므로 따로 두지 않는다.
- 대신 손버릇은 맞춘다 — 트리에서 에이전트를 더블클릭하면 **그 에이전트만 고르기**(따라감 선택을 갈아 치움).
  다시 더블클릭하면 그 전 선택으로 돌아간다.

## 8. 데이터 — 보이는 판만 받는다

- **보이는 판** = 창에 떠 있고, 판 묶음에서 앞에 있는 탭. 접힌 탭·숨은 창은 받지 않는다.
- **XLog** — 지금 창마다 오브젝트를 알리면 Rust 가 합쳐 스트림 하나를 연다(`start_xlog_stream`,
  `xlog_subs`). 이것을 **판마다** 로 바꾼다(키를 창 라벨 → 판 id). 점은 판마다 제 대상만 그린다.
  판이 늘어도 콜렉터 요청 수는 같다(콜렉터마다 스트림 하나).
- **점 보관은 앱 전체 예산 하나** — 10장.
- **카운터** — 지금은 스트림이 하나다(`start_counter_stream` 이 토큰 하나 — 새로 열면 앞의 것이 멈춘다).
  한 번에 «오브젝트 묶음 × 카운터 목록» 한 벌만 받는다.
  XLog 와 같이 **판마다 구독(오브젝트 × 카운터 이름)을 알리고 Rust 가 합쳐** 콜렉터마다 2초 폴링 한 번,
  받은 것을 판마다 나눠 준다.
- **EQ · Active · Summary · Service Group** — 지금처럼 판이 보일 때만 묻는다(`enabled`). 같은 대상·같은
  주기의 판이 둘이면 한 번 물어 나눈다(P2 에서 겹침이 실제로 생기면).
- **Alert** — 지금처럼 앱 전체가 받는다(배지).

## 9. XLog 판 안

- 툴바(실시간/과거·구간·거름·트랜잭션 찾기)는 **판 머리 아래** 판마다 둔다 — 지금은 «지금 판» 하나의
  툴바를 위에 둔다. 좁은 판에서는 접는다.
- 드래그로 고른 트랜잭션은 **트랜잭션 목록 판(`txList`)** 으로 간다. 목록 판은 «마지막에 고른 XLog 판» 을 따른다
  — 지금의 «지금 판» 개념. 목록 판이 없으면 그 XLog 판 아래에 붙여 연다.
- 키: 원본의 `↑`/`↓`(Y축 최대) · `+`/`-`(시간 폭) · `←`/`→`(10초 이동) 을 차트에 넣는다.
  지금의 휠·Ctrl+휠은 남긴다.
- 제목: `XLog - {대상}`, 부제 `ⓢ{콜렉터} | {대상}'s XLog {Realtime|과거 구간}` — 원본과 같은 꼴.

## 10. 점 보관 — 앱 전체 예산

- 지금은 XLog 탭마다 최대 10만 건(설정 `buffer_max`)을 따로 든다. 판이 16개면 따로 드는 방식은 예측이 안 된다.
- **앱 전체 예산 하나**를 판들이 나눠 쓴다. 예산을 넘으면 **판 상관없이 가장 오래된 점부터** 버린다 —
  그러면 모든 실시간 판이 «같은 최근 N분» 을 들게 되어 판끼리 견주기 쉽고, 한가한 판이 몫을 헛되이 쥐지 않는다.
- **같은 대상·같은 조건의 판은 점 저장소를 함께 쓴다**(따라감 판 여럿 등) — 두 번 세지 않는다.
- 과거 구간 판도 예산에 든다. 조회가 예산을 넘기면 받은 데까지 담고 «예산에 닿아 여기까지» 를 판에 적는다
  (트랜잭션 찾기의 상한 표시와 같은 꼴).
- 판 머리에 «최근 N분 보관 중» 을 적는다 — 판이 늘면 이 시간이 준다는 것이 보인다.
- **예산은 올린다.** 건당 ≈370B(트랜잭션 찾기의 «100만 ≈ 370MB» 와 같은 화면 모양) 기준:

  | 예산 | 메모리(점만) | |
  |---|---|---|
  | 50만 | ≈185MB | 저사양 |
  | **100만 (기본)** | ≈370MB | 지금 탭 하나 10만의 10배 |
  | 200만 | ≈740MB | |
  | 300만 | ≈1.1GB | 상한. 고를 때 경고 |

  기본은 **100만**으로 정했다. 설정 «XLog 보관 상한» 을 이 예산으로 바꾸고,
  지금 값(탭당 10만)은 «예산 = 지금 값 × 지금 탭 수» 로 옮긴다.
- 메모리 수치는 계산값이다. P1 에서 판 16개·예산 100만으로 실제 WebView 메모리를 잰다 — 크게 어긋나면 다시 정한다.
- **실측 (P1-3, 브라우저·판 16개·서버 4대·실시간)**: 점 100만~120만에서 메모리 정리 뒤 300~450MB(계산 «100만 ≈ 370MB» 와 맞다),
  화면 약 45fps. 처음에는 예산을 정리(5초마다) 때만 봐서 초당 19만 건을 넣는 시험에서 300만까지 넘쳤다 — 점을 받을 때도
  0.5초마다 보게 고쳤다. 넘는 폭은 «0.5초 동안 들어오는 양» 까지다.
- 뗀 창은 창마다 따로 예산이다(창마다 화면이 따로 돈다). 창 여러 개를 쓰면 그만큼 더 쓴다 — P4 에서 창끼리 나눌지 본다.

## 13. 대시보드 프리셋

원본의 «퍼스펙티브». **대시보드 하나 = 판 나무(나눔·몫) + 판마다의 종류·대상(따라감/고정)·조건** 에 이름을 붙인 것.
(«작업 공간» 은 지금 서버 묶음을 가리키므로 이쪽은 **대시보드** 라 부른다.)

- **기본 제공** — `원본 기본`(12장) · `XLog 만`(큰 XLog + 목록) · `XLog 2×2`(따라감 1 + 빈 고정 3, 서비스 비교) ·
  `카운터 위주` · `분석`(지금 Visualize 탭의 배치, 14장). 기본 제공은 고쳐 쓸 수 있지만 원래대로 되돌릴 수 있다.
- **내 대시보드** — 지금 배치를 이름 붙여 저장 · 덮어쓰기 · 이름 바꾸기 · 지우기 · «시작 대시보드» 로 지정.
- **전환** — 위쪽 탭 줄 자리에 대시보드 이름을 늘어놓는다: `원본 기본 | 결제 비교 | 장애 대응 …`. 한 번 눌러 바꾼다.
  - 바꿀 때 지금 대시보드의 판 상태(받아 둔 점·고른 조건)는 **버리지 않고 숨긴다** — 돌아오면 그대로.
    숨은 대시보드의 판은 «보이는 판» 이 아니므로 받지 않는다(8장). 돌아오면 그 사이 것을 다시 받는다.
  - 고친 뒤 저장하지 않았으면 이름 옆에 `•`, `저장` · `되돌리기`(저장본으로).
- **대상은 이름으로 남긴다**(서비스 묶음·종류·에이전트 이름) — 다른 날·Task 가 갈린 뒤에도 그대로 열린다.
  고정 대상이 지금 콜렉터에 없으면 판에 «대상 없음 — 대상 고르기» 를 띄운다.
- **팀 공유** — 대시보드를 파일로 내보내기·가져오기. 팀 표준 대시보드를 나눠 쓴다.
- **서버 묶음과 엮기(선택)** — 서버 묶음(작업 공간)에 «붙으면 이 대시보드로» 를 정한다. 운영이면 운영 대시보드.
- **창 여러 개** — 모니터 구성이 PC 마다 달라 창 위치까지 남기면 엉뚱한 곳에 뜬다. 대시보드에는 **창마다의 판 나무와
  창 개수만** 남기고, 창 자리는 그 PC 에서 마지막에 둔 곳을 쓴다(없으면 메인 창 옆).
- 저장: `config.json` 의 `dashboards` (이름 → 배치) 와 `active_dashboard`. P1 부터 배치를 «이름 붙은 하나» 로
  저장해 두면 P4 에 목록으로 넓히기만 하면 된다.

### P4b 구현 메모 (2026-11-17)

- **Visualize 는 쪼개지 않고 통째 판(`visualize`)** 으로 넣었다(14장의 제안과 다르다). 안의 KPI · 격자 · 타임라인 · 분포 · 순위가
  임계값 · 표본 훅을 함께 써서, 쪼개면 판마다 같은 것을 따로 묻게 된다. 쪼개 쓰고 싶다는 말이 나오면 그때 훅을 위로 올린다.
- Counter 탭은 `카운터 전체` 판(`counterBoard`, App 의 `CounterBoard`). 판의 서버는 카운터 스트림에 합친다(카운터 판과 같다).
- Active 탭은 이미 `Active 목록` 판, Alert 탭은 `Alert` 판이었다 — 탭만 뺐다.
- 기본 제공 `분석`(Visualize 판) · `카운터 위주`(카운터 전체 판). 업데이트한 사람도 목록에 붙는다(처음 켤 때만 만든다).
- 대시보드를 바꾸면 **따라감 판은 바꾸기 전 트리의 고르기를 이어받는다** — 트리는 하나인데 대시보드마다 고르기가 따로면
  바꿀 때마다 «왼쪽에서 고르세요» 가 떴다.
- Visualize 판에서 파고들기 → XLog 판으로 옮겨 조건을 건다(`focusXLog`). 없으면 옆 탭으로 연다.
- XLog 판이 없는 대시보드는 아래 트랜잭션 목록을 접는다(고른 트랜잭션이 있으면 남긴다).
- 저장된 `activeTab` 이 예전 탭(active · counter …)이면 대시보드로 읽는다.
- 통계 화면에 있는 동안은 메인 창의 XLog 실시간 스트림을 멈춘다(판이 내려가 있어 받아도 버린다).

### 점검에서 고친 것 (2026-11-18)

- 트리에서 연 판이 **지금 판 묶음의 탭**으로 들어 보던 XLog 가 가려졌다 → 지금 판 **오른쪽에** 세운다(`openBeside`).
  크기를 안 주면 같은 줄의 판이 모두 고르게 다시 나뉘어(dockview `Sizing.Distribute`) 원본 기본의 Alert · 카운터 열 폭까지 바뀌었다
  → 기준 판의 반(`initialWidth`).
- `각각 XLog` 가 대시보드 **모든 판**을 격자로 다시 놓았다 → 연 판들만, 누른 XLog 판의 자리 안에서. 연 판은 그 판 묶음의 탭으로 넣은 뒤 나눈다.
- 격자 크기를 옮긴 직후에 맞추면 아직 서지 않은 묶음 크기로 계산해 고르지 않았다 → 자리는 옮기기 전에 재고, 크기는 다음 프레임에.
  짧은 마지막 줄은 그 줄의 판 수로 나눈다. 정렬 뒤 지금 판이 엉뚱한 판으로 바뀌던 것도 고쳤다.
- `Ctrl+R` 이 지금 판이 카운터 · Active 목록 판이어도 그 판을 과거로 돌려 Active 목록의 트래픽이 멎었다 → XLog 판일 때만.
- XLog 스트림에 지금 판의 서버를 늘 더해, 지금 판이 카운터 판 · 과거 XLog 판이어도 그 서버 점을 받았다 → 보이는 실시간 판만.
- (실제 앱) 다시 켜면 원본 기본의 지금 판이 XLog 가 아니라 Alert 로 바뀌었다 — 저장된 «보이는 판» 을 예전 분할 상한(4)으로 잘라
  XLog 가 빠졌다 → 배치가 있으면 자르지 않는다(`withSplit`).
- 실제 앱(디버그 빌드 · Xvfb · 저장소의 가짜 콜렉터 · WebDriver)에서 본 것: 접속 · XLog 점 · 대시보드 바꾸기 · 새 창 떼기 ·
  다시 켜면 뗀 창이 되살아남 · 합치기 · 배율 2배에서 캔버스 글자 크기. Windows 의 화면 배율 · 창 밖으로 끌어 떼기는 못 봤다.

### 둘러보기 후속 1차 (2026-11-18)

- 메뉴가 화면보다 길면(판 `+` 의 카운터 40여 개) 아래 항목을 고를 수 없었다 → 메뉴 높이를 창에 묶고 안에서 굴린다.
- 트리 오른쪽 메뉴 21줄에 가름선 — 판 열기 / 카운터 / 각각 열기 / 들여다보기.
- 고정 판 이름에 대상(`실시간 · shop-1`) — `실시간 2 · 3 · 4` 로는 어느 서비스인지 몰랐다.
- 빈 판 문구를 판마다 크게 되풀이하지 않는다(원본 기본에서 일곱 번). 따라감 판에 «이 판을 누르고» 라고 하던 것도 고쳤다.
- XLog 가 아닌 판이 지금 판일 때 위 줄을 툴바와 같은 높이(33px)로 — 판을 오갈 때 아래 판들이 튀었다. XLog 판이 없는 대시보드에서는 «XLog 판을 누르면» 을 빼다.

### 둘러보기 후속 2차 (2026-11-18)

- 트랜잭션 목록은 **고른 것이 없으면 제목 줄만**(28px) — 늘 220px 를 빈 표가 먹었다. 구간을 고르면 펼친다.
- 고르지 않은 서버를 흐리게(투명도 45%) 하지 않는다 — 꺼진 서버와 구별이 안 됐고 다크 테마에서 안 읽혔다. 글자 색만 낮춘다.
- 지금 판은 머리를 강조색으로 옅게 칠하고 탭 이름을 굵게(전에는 아래 선 하나).
- 판 `+` 메뉴의 카운터는 자주 보는 6개 + `카운터 · 전체 목록 (39)…`(같은 자리에 전부를 다시 띄운다).
- 좁은 판의 `∨ 1` — 탭이 줄어들게(말줄임), 360px 아래 판은 머리에서 `⊞` 를 뺀다. XLog 가 아닌 판에는 늘 눌리지 않던 `↗` 를 두지 않는다.

## 14. 위쪽 탭은 어떻게

- XLog · Counter · Active · Alert 는 **판이 된다** → 위쪽 탭에서 빠진다. 그 자리에 대시보드 이름이 선다(13장).
- **Visualize 는 판으로 쪼갠다** (제안 · Q2). 지금 탭은 KPI 줄 · 인스턴스 격자 · 쌓인 타임라인 · 응답시간 분포 ·
  느린 서비스 · Active 를 한 화면에 모은 것이다. 모두 «고른 서버에 대해» 보는 것이라 **트리 따라감 판**과 성격이 같다.
  `kpi` · `instances` · `timeline` · `distribution` · `topServices` 판으로 나누고, 지금 Visualize 탭의 배치는
  기본 제공 대시보드 `분석` 으로 남긴다. 위쪽에 따로 두지 않는다.
- **통계는 대시보드 밖의 «도구 화면»으로 남긴다** (제안 · Q2). 통계는 판과 성격이 다르다 — 트리를 따르지 않고
  폼에서 대상을 따로 고르며, 몇 분씩 도는 작업과 지난 결과 목록이 있고, 넓은 표를 화면 가득 쓴다.
  대시보드 줄 오른쪽 끝에 `통계` 를 두어 누르면 대시보드 자리를 통계 화면이 차지한다(대시보드는 숨긴 채 그대로).
  - 트리 오른쪽 클릭 `이 대상으로 통계…` — 폼에 대상을 채워 통계 화면을 연다.
  - 통계 결과의 `XLog 탭에서 열기`(트랜잭션) 는 «지금 대시보드의 XLog 판» 에서 연다.
- 위쪽 줄: `[원본 기본] [결제 비교] [분석] …` ⋯ `[통계]`. `Ctrl+1~9` = N 번째 대시보드, 통계는 대시보드 다음 번호.

## 15. 이행 · 호환

- 처음 켤 때 지금 설정(`xlog_tabs`·`xlog_split`·`xlog_windows`)을 판 배치로 옮긴다 — XLog 탭은 XLog 판,
  분할은 나눔, 뗀 창은 창. 옮긴 뒤 옛 키는 지운다.
  XLog 탭이 하나면 따라감 판, 여럿이면 지금 판은 따라감 · 나머지는 각자 선택으로 고정 판이 된다.
  옮긴 것은 대시보드 `내 배치` 로 남는다.
- 옮길 것이 없으면 12장의 기본 배치.
- 설정 «XLog 보관 상한»(탭당) 은 «XLog 점 예산»(앱 전체) 으로 옮긴다 — 10장.
- 지금 단축키는 그대로 두되 `Ctrl+1~6`(위쪽 탭) 은 `Ctrl+1~9` «N 번째 대시보드» 로 뜻을 바꾼다.

## 17. 정할 것

**확인 대기 (제안)**
2. **Visualize · 통계 자리** — Visualize 는 판으로 쪼개고(대시보드 `분석`), 통계는 대시보드 밖 도구 화면(14장).
3. **도킹** — `dockview-react` + 창마다 하나 + 새 창은 Tauri 창(5장). P1 첫 일로 넷을 확인하고 확정.

**정한 것**
- (11-17) 판은 트리 따라감(기본)과 고정 두 가지 — 왼쪽 트리는 그대로 둔다(4장).
- (11-17) 점 보관은 앱 전체 예산을 나눠 쓴다(10장). **기본 100만**.
- (11-17) 배치는 대시보드 프리셋으로 저장·전환한다(13장).
- (11-17) **트리 맨 위를 콜렉터로 나눈다**(원본처럼). 판 대상은 여러 콜렉터에 걸칠 수 있다(`selection`).
  콜렉터가 하나면 콜렉터 줄을 생략한다.
- (11-17) **`Ctrl+1~9` = N 번째 대시보드.**
- (11-17) **원본에만 있는 화면은 «원본에 있고 지금 앱이 이미 받아 오는 데이터» 면 판으로 넣는다. 기본 배치에는 띄우지
  않는다** — 판 메뉴·트리 오른쪽 클릭에서 연다. 새로 데이터를 받아야 하는 화면(Unique Visitor 등)은 이번 범위 밖.
  넣을 후보(지금 받는 데이터로 그릴 수 있는 것)는 P2 시작 때 데이터 출처와 함께 표로 확정한다.

## 18. 위험

- **App.tsx 가 3,600줄이고 상태가 «지금 판» 하나를 전제로 얽혀 있다.** P1 은 상태를 판 단위로 떼어 내는 일이
  대부분이다. 기능을 한 번에 옮기지 말고 XLog 판부터 동등하게 만든 뒤 넓힌다.
- 판이 많으면 폴링이 는다 — 판마다 구독을 합쳐 콜렉터당 요청 수를 지금과 같게 유지한다(8장).
- 판이 많고 예산이 크면 메모리 — 예산 상한(300만)에서 경고하고, 숨은 대시보드는 받지 않는다(13장).
  가장 오래된 점부터 버리므로 판이 늘면 판마다 보이는 과거가 짧아진다 — 판 머리에 «최근 N분» 을 적어 드러낸다.
- 원본과 «비슷하게» 의 기준이 사람마다 다르다 — P0·P1 이 끝날 때마다 실사용자에게 보인다.
