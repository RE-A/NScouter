> 이 문서는 **쓰는 법**을 다룬다. 빌드·개발은 [개발 가이드](dev-guide.md), 배포는 [배포 가이드](deploy-guide.md).

## 1. 접속

앱을 켜면 상단 바에 접속 폼이 있다.

| 칸 | 값 |
|---|---|
| Host | 콜렉터 주소 (예: `127.0.0.1`) |
| Port | 콜렉터 TCP 포트 (기본 `6100`) |
| User / Password | 콜렉터 계정 |

**자동 연결**을 켜면 다음 실행부터 이 정보로 바로 붙는다.
다만 **비밀번호가 `config.json` 에 평문으로 저장된다** — 공용 PC 에서는 켜지 말 것.
끄면 저장돼 있던 비밀번호도 함께 지워진다.

붙었는지는 상단 왼쪽 배지(초록 점 + 서버 이름)로 안다. 끊을 때는 `연결 해제`.

---

### 1.1 서버를 여러 개 두고 갈아타기

운영·QA 처럼 콜렉터가 여럿이면 매번 호스트와 계정을 다시 칠 것 없이 **골라서 옮긴다.**
접속에 성공한 서버는 자동으로 목록에 남고, 헤더의 서버 버튼(▾)에서 고른다.

- **한 번에 한 서버다.** 두 콜렉터를 나란히 보는 것이 아니라 빠르게 옮겨 가는 기능이다
- 갈아타면 **화면이 새로 시작한다** — 오브젝트 해시가 서버마다 달라 필터·상세 탭을
  그대로 둘 수 없다. 창 크기·글자 크기 같은 설정은 그대로다
- 목록에는 `host:port · 계정` 이 함께 보인다. 이름만으로는 운영과 QA 를 못 가른다
- **비밀번호는 «자동 연결» 을 켠 서버만 저장된다**(config.json 에 평문). 저장 안 한 서버는
  목록에 «비밀번호 물음» 이라고 적히고, 고르면 접속 폼에 호스트·계정이 채워진 채로
  비밀번호만 묻는다
- `✕` 로 목록에서 지운다. 지워도 접속 정보만 사라질 뿐 서버는 그대로다

## 2. 화면 구성

```
┌ 상단 바 ─ 서버 배지 · XLog / Counter / Alert 탭 · 알림 배지 · 설정(⚙)
├ 왼쪽 SERVICES ─ 붙어 있는 오브젝트(에이전트) 목록
└ 본문 ─ 선택한 탭
```

**왼쪽 목록의 클릭은 두 가지다.**

| 조작 | 결과 |
|---|---|
| 왼쪽 클릭 | 그 오브젝트만 보기 (여러 개 고를 수 있다). 아무것도 안 고르면 전체 |
| **오른쪽 클릭** | 그 오브젝트의 상세 메뉴 — 속성·스레드·힙·설정 등 (→ [6장](#6-오브젝트-들여다보기)) |

`전체` 를 누르면 선택이 풀린다.

**목록은 타입으로 묶여 있다.** 묶음 머리를 누르면 접힌다 — 접혀 있어도
`살아있는 수/전체` 는 보인다. 위의 찾기 칸은 **이름과 타입 둘 다** 뒤지므로
`CJFW`(시스템)로도 `BO`(이름 일부)로도 찾는다. 이름은 짧은 이름이 아니라
전체 경로로 보기 때문에 `/PRD-FSCP/` 같은 중간 마디로도 걸린다.
찾는 동안에는 접어 둔 묶음도 펼쳐진다.

## 2.1 SERVICES 목록 — 묶기

오브젝트가 백 개를 넘으면 평평한 목록에서는 찾을 수가 없다. 두 가지로 묶을 수 있다.

| 묶기 | 기준 | 예 |
|---|---|---|
| `타입` | 오브젝트 종류 (`obj_type`) | tomcat · datasource · linux |
| `그룹` | 이름의 **첫 마디(호스트)** | `/CJFW` · `/order-app` |

Scouter 의 이름 규칙이 `/{host}/{name}` 이라 첫 마디가 호스트다
(ASIS 도 같은 자리를 잘라 호스트를 찾는다). **앱과 그 앱의 datasource 가 한자리에 모인다** —
`/order-app/order-app` 과 `/order-app/order-app/HikariPool-1` 이 같은 `/order-app` 이다.

**두 기준은 서로를 대신하지 못한다.** 타입은 「무엇인가」, 그룹은 「어느 호스트에 있는가」다.
운영에서 `obj_type` 에 시스템 이름을 넣어 쓰면(CJFW · PRD-ORD) 둘이 비슷해 보이지만,
그때도 나누는 결이 다르다.

- 고른 기준은 **껐다 켜도 남는다**
- 검색은 기준과 무관하게 이름 전체 경로와 타입 둘 다 본다
- 마디가 하나뿐인 이름(`test-host`)은 `(그룹 없음)` 으로 모인다

## 3. XLog 탭 — 트랜잭션 보기

### 3.1 실시간 / 과거

| 모드 | 쓰임 |
|---|---|
| **실시간** | 지금 들어오는 트랜잭션이 오른쪽에서 흘러 들어온다 |
| **과거** | 시각 두 개를 정하고 `조회` — 지난 구간을 그대로 본다 |

과거 모드에서는 차트 위에서:

- **휠** — 커서를 고정한 채 확대·축소
- **Shift + 휠** — 시간축 이동

이미 받아 온 구간 안이면 다시 조회하지 않는다.

### 3.2 Y축과 범위

`Y축` 은 점의 높이를 무엇으로 볼지다 — `Elapsed(sec)` · `CPU(ms)` · `SQL Time(sec)` · `SQL Count` ·
`ApiCall Time(sec)` · `ApiCall Count` · `Heap Used(KB)`.
`범위` 는 가로축이 담는 시간(1·5·10·30분)이다.

### 3.2.1 「3초짜리가 왜 맨 밑에 있지」

**Y축이 Elapsed 가 아니면 점 높이는 응답시간이 아니다.** 예를 들어 Y축이 `SQL Time` 일 때,
다른 앱을 6초 기다렸지만 SQL 은 한 건도 안 쓴 요청은 **0 에 찍힌다.** 맞는 그림이다.

그래서 Y축이 Elapsed 가 아닐 때는 **트랜잭션 목록에 그 축의 값을 한 칸 더** 보여준다:

```
URL                      ELAPSED    SQL Time
/shop/lab/slow<GET>      6,006ms    0ms       ← 6초 걸렸지만 SQL 은 0
```

두 수가 한 줄에 있어야 「왜 밑에 있나」가 아니라 「SQL 을 안 썼구나」로 읽힌다.
축 이름이 툴바와 차트 오른쪽 위에 적혀 있어도, 숫자 하나만 보이면 그게 점 높이인 줄 안다.

### 3.3 필터

필터는 **점과 목록에 함께** 걸린다.

| 필터 | 설명 |
|---|---|
| 에러만 | 실패한 트랜잭션만 |
| 응답 `이상` / `미만` + 초 | 예) `이상 2` = 2초 이상. 빈 칸이나 `0` 이면 조건 없음 |
| 서비스 | URL 의 일부 (예: `orders`) |
| IP | 호출자 IP 의 일부 (예: `10.89.`) |

**`이상`/`포함` 을 누르면 `미만`/`제외` 로 뒤집힌다.**
`IP 제외 10.89.2.17` 이면 그 IP **만 빼고** 보이고, `응답 미만 2초` 면 2초 **미만**만 보인다.
각 칸 오른쪽 `✕` 로 그 조건만 지운다.

### 3.3.1 조건 여러 줄 — `필터` 창

툴바의 서비스·IP 칸은 **한 줄짜리 뷰**다. 운영에서 하는 말은 «이 두 URL 만» 이거나
«헬스체크·모니터링은 빼고» 라서 한 칸으로는 안 된다. 툴바의 `필터` 를 누르면 창이 열린다.

규칙은 하나다 — **자리 안에서는 OR, 자리끼리는 AND**.

| 걸어 둔 것 | 뜻 |
|---|---|
| 서비스 포함 `/shop/order` + 포함 `/shop/cart` | 둘 **중 하나**면 통과 |
| 서비스 제외 `/health` + 제외 `/monitor` | 둘 **중 하나라도** 맞으면 뺀다 |
| 서비스 포함 `/shop` + 제외 `/cart` | `/shop` 중에서 `/cart` 만 뺀다 (제외가 세다) |
| 서비스 포함 `/shop` + IP 포함 `10.89.` | **둘 다** 만족해야 통과 |

- 툴바 칸은 각 자리의 **첫 줄**을 고친다. 창에서 세 줄을 걸어 두고 툴바에서 글자를
  고쳐도 나머지 줄은 그대로 있다. 툴바의 `필터 +N` 은 칸에 안 보이는 줄 수다
- **빈 줄은 조건이 아니다.** `+ 제외` 를 눌러 생긴 빈 줄이 전부를 지우지 않는다
- 응답시간(이상/미만)과 «에러만» 도 창에서 함께 건다
- **대상 서버는 창에서 바꾸지 않는다** — 왼쪽 SERVICES 목록이 그 일을 한다.
  두 곳에서 같은 것을 바꾸면 어느 쪽이 이겼는지 알 수 없다
- 걸어 둔 조건은 껐다 켜도 남는다(7.2)

#### 자주 쓰는 조건 담아 두기

장애를 볼 때 거는 조건은 매번 새로 짜는 것이 아니라 «결제만»·«헬스체크 빼고»처럼
몇 벌이 돌아가며 쓰인다. 창 아래에서 **이름을 붙여 담아 둔다.**

- 목록에서 이름을 누르면 **조건만** 얹힌다. **대상 서버는 그대로다** —
  서버 해시는 콜렉터마다 달라, 담아 둔 것에 서버까지 넣으면 다른 서버에서 불러왔을 때
  아무것도 안 걸린다
- 지금 걸린 조건과 같은 것에는 `●` 가 붙는다. 목록만 봐서는 무엇이 걸려 있는지 모른다
- 같은 이름으로 담으면 **덮어쓴다**. 버튼이 «덮어쓰기» 로 바뀌어 미리 말해 준다
- 불러오면 이름칸이 채워진다 — 고쳐서 같은 이름으로 다시 담는 흐름이 잦다

### 3.4 구간을 골라 목록으로

차트에서 **드래그**하면 그 사각형 안의 트랜잭션이 아래 표에 나온다.
시간 · 서버 · URL · IP · 응답시간 순이고, 행을 누르면 오른쪽에 상세가 열린다.

### 3.5 프로파일 검색 — 트랜잭션 **안**의 텍스트 찾기

표 위의 `프로파일 검색` 은 목록의 URL 이 아니라 **각 트랜잭션의 프로파일 내용**을 뒤진다.
SQL 문장, 바인딩 값, API 주소, 메서드 이름, 에러 메시지, 로그 메시지가 대상이다.

1. 먼저 차트에서 구간을 드래그한다 (검색 대상이 그 구간이다)
2. 검색어를 넣고 Enter
3. `1,650 / 2,101 흐는 중 · 적중 652건` 처럼 진행 상황이 보이고, 오래 걸리면 `중단` 할 수 있다

적중한 행에는 걸린 자리가 함께 뜬다 (`apicall-addr  shop-app:8081` 처럼 **어디서** 걸렸는지).
한 트랜잭션 안에서 여러 번 걸리면 `+N` 배지가 붙는다.

> 검색은 앱이 아니라 **콜렉터 쪽에서** 훑는다. 프로파일 전체를 화면으로 끌고 오지 않으므로 건수가 많아도 앱이 멈추지 않는다.

### 3.5.1 넓은 구간에서 찾기 (툴바 `찾기`)

프로파일 검색(3.5)은 **고른 구간 안**을 뒤진다. 그래서 「오늘 오전 내내 중 이 서비스만」은
구간을 잘게 나눠 여러 번 드래그해야 했다. 그걸 한 번에 하는 입구다.

**서버가 걸러서 보내 준다.** 다 받아서 화면에서 거르는 것보다 빠르다 — 창이 넓을수록 더:

| 창 | 다 받고 화면에서 거름 | 서버가 거름 |
|---|---|---|
| 2분 | 167ms | 45ms |
| 30분 | 1,116ms | 144ms |

- 조건: 구간 · 오브젝트 · 서비스 · IP · 로그인 · 설명 (+ 앱 자유 필드 text1~5)
- **그냥 치면 「포함」으로 찾는다.** `*` 를 직접 쓰면 그 자리만 아무 글자로 본다
- 오브젝트는 **하나만** 고를 수 있다 — 서버가 하나만 받는다. 「전체」로 두면 안 가린다
- 결과는 아래 트랜잭션 목록으로 들어간다. 행을 눌러 상세를 열고 프로파일 검색을 거는 건 그대로다

> **상한 500건에서 잘린다.** 서버 설정(`req_search_xlog_max_count`)의 기본값이고,
> **서버는 잘렸다는 신호를 아무것도 주지 않는다.** 그래서 창을 열 때 상한을 물어보고 적어 두며,
> 결과가 상한에 닿으면 목록 머리에 「상한 500건에서 잘렸을 수 있습니다」를 단다.
> **그 경고가 보이면 「없다」고 읽으면 안 된다** — 조건을 좁히거나 구간을 나눠 다시 찾을 것.
>
> 이 상한 때문에 스캐터 드래그를 대체하지는 않는다. 좁은 구간은 드래그가 낫다.

### 3.6 상세 패널

행을 누르면 오른쪽에 열린다.

**요약** — 응답시간, SQL 시간·건수, API 시간·건수.

**호출 흐름** — 이 요청이 거쳐 간 앱들. 토글이 둘이다.

| 토글 | 보이는 것 |
|---|---|
| `앱` | 앱 단위 시간 막대 — *어느 앱이* 느렸나 |
| `상세` | 사용자 IP → 서비스 → SQL·API 호출까지 내려간 나무 — *그 앱이 무엇을* 불렀나 |

`상세` 에서 `SQL` / `API 흐름` 체크를 끄면 **잎만** 사라진다. 이어진 앱은 남는다 — 흐름이 끊기면 안 되기 때문이다.
같은 대상을 여러 번 불렀으면 한 줄로 접히고 `×3` 처럼 횟수가 붙는다. 같은 SQL 50개가 50줄로 흩어지면 N+1 이 오히려 안 보인다.
다른 스레드로 넘어간 작업(비동기)도 그 스레드의 트랜잭션으로 이어 붙는다.

**프로파일** — 트랜잭션이 실제로 한 일을 순서대로.

- `목록` / `요약` 전환. 요약은 같은 항목을 묶어 횟수·합계·평균으로 보여주고 정렬할 수 있다
- 검색어가 걸린 스텝은 강조되고, 여러 곳이면 머리의 `‹ 1/2 ›` 로 옮겨 다닌다
- 긴 SQL 은 접혀 나온다. **`펼치기` 를 누르면 절 단위로 줄을 나눠 보여준다** —
  `select` · `from` · `join` · `where` · `order by` 가 각자 줄을 갖고 `and`/`or`/`on` 은 한 칸 들여쓴다.
  접힌 상태는 세 줄뿐이라 나누지 않는다(그러면 낱말 세 개만 보인다).
  **글자는 하나도 안 바뀐다** — 줄바꿈과 들여쓰기만 넣는다. 원문 한 줄은 마우스를 올리면 나온다
- `THR` 스텝은 다른 스레드로 넘어간 자리다. 누르면 그 스레드의 트랜잭션이 열린다
- SQL 옆의 `~1행` 은 에이전트가 보고한 갱신 건수다. 읽기(SELECT)에는 안 붙는다.
  **물결(`~`)은 어림수라는 뜻이다** — 같은 연결로 UPDATE 를 잇달아 하면 앞 문장에 얹혀
  실제보다 크게 나온다(1행짜리가 `~2행`). 단독 실행에서는 정확하다
- `에이전트가 SQL 문장을 받지 못했습니다` 가 뜨는 자리가 있다. 자동 생성 키를 쓰는
  INSERT 는 드라이버가 문장 없이 PreparedStatement 를 만들어 에이전트가 문장을 못 얻는다 —
  콜렉터까지 문장이 오지 않아 복원할 수 없다. 이때 옆의 `1행` 이 유일한 단서다

**속성** — CPU, Heap, IP, TxID, GxID.

### 3.7 여러 트랜잭션을 나란히 — 상세 탭

행을 여러 개 누르면 **탭으로 쌓인다.** 하나만 열려 있으면 탭 줄은 나오지 않는다.

느린 트랜잭션을 볼 때 실제로 하는 일은 «이건 왜 느리지» 가 아니라
**«정상인 것과 뭐가 다르지»** 다. 하나만 열리면 두 개를 번갈아 열어야 하고,
그 사이에 실시간 목록이 흘러가 방금 본 것을 다시 못 찾는다.

- 탭 이름은 **서비스명 + 시각 + 응답시간**이다. 같은 서비스를 두 개 열면 이름이 같아지므로 시각이 기준이 된다
- 같은 트랜잭션을 다시 누르면 탭이 늘지 않고 그리로 옮겨 간다
- `Ctrl+Tab` 으로 오간다. `Ctrl+W` 로 지금 탭만 닫고, `모두 닫기` 로 전부 닫는다
- **여덟 개까지** 열린다. 넘치면 가장 오래 안 본 탭이 닫힌다 — 지금 보는 것과 방금 본 것은 남는다

### 3.7.1 상세 안에서 찾기

프로파일 머리의 `이 안에서 찾기` 칸은 **연 트랜잭션 안에서만** 찾는다.
위쪽 검색바(3.5)는 «어느 트랜잭션에 그 SQL 이 있나» 를 묻는 자리라 목록이 바뀌지만,
여기는 이미 연 것 안에서 스텝을 짚을 뿐이다. `‹ 1/3 ›` 로 걸린 자리를 오간다.
칸을 비워 두면 위쪽 검색어를 그대로 따른다.

요약 표에서는 **줄을 누르면 목록의 그 스텝으로 간다.** 같은 쿼리가 여러 번이면
처음 나온 것으로 간다 — «그래서 언제 돌았는데» 가 다음 질문이기 때문이다.

### 3.8 프로파일을 파일로 남기고 다시 열기

**콜렉터는 오래된 트랜잭션을 지운다.** 어제 본 그 트랜잭션을 내일 다시 열려면
그때 남겨 둬야 한다. 남에게 보낼 때도 마찬가지다.

- **저장**: 상세 패널 오른쪽 위 `저장`. 지금 보고 있는 것 그대로 파일이 된다
- **열기**: XLog 툴바의 `저장본` → 목록에서 고른다. **접속하지 않아도 열린다**

파일은 `{데이터 폴더}/profiles/` 에 `20260830-141203_shop_order_z1pa9p0.json`
처럼 쌓인다(데이터 폴더는 설정에서 정한다. 기본은 실행 파일 옆). 창에 경로가
적혀 있고 `폴더 열기` 로 탐색기에서 연다 — **지우는 것은 폴더에서** 한다.

**서비스명·SQL·에러 문구가 풀린 채로 들어간다.** Scouter 는 이 문장들을 트랜잭션에
싣지 않고 해시만 보내며, 진짜 문장은 콜렉터의 사전에 있다. 해시만 저장하면 며칠 뒤
사전이 밀려났을 때 `[0x1a2b3c]` 만 남는다. 그래서 화면이 이미 풀어 둔 것을 같이 넣는다.

- 저장본 탭에는 시각 옆에 `· 저장본` 이 붙는다. 옆 탭들과 달리 **지금 흐르는 것이 아니다**
- 저장본은 다시 저장할 수 없다(`저장` 이 나타나지 않는다). 이미 파일이다
- 기존 Scouter 클라이언트가 남긴 `xlog.xlog`/`xlog.prof` 는 **열지 못한다.**
  그쪽은 해시가 안 풀린 와이어 포맷이라 사전 없이는 이름이 안 나온다

## 4. Counter 탭 — 지금 서버 상태

| 패널 | 답하는 질문 |
|---|---|
| 액티브 서비스 | 지금 **몇 건**이 어디에 몰려 있나 |
| 요약 | 무엇이 느렸나 · 어디서 실패하나 · 어느 호출자(IP)에서 왔나 |
| 토폴로지 | 외부 유입 → 애플리케이션 → 의존 자원 |
| 서비스 그룹 | 무엇이 들어오는가 / 서버가 견디는가 |
| 애플리케이션 · 호스트 · 커넥션 풀 | 카운터 차트 (오브젝트 종류별) |
| 호스트 · 5분 집계 | 실시간보다 긴 흐름 |

> **토폴로지가 "수집이 꺼짐" 으로 나오면** 에이전트 설정에서 `counter_interaction_enabled` 를 켜야 한다.
> 에이전트가 기본으로 수집하지 않는 항목이다.

### 4.1 볼 서버 고르기

구역(애플리케이션·호스트·커넥션 풀) 머리의 `서버` 버튼에서 **그릴 서버를 고른다.**
한 타입에 열 대가 붙으면 선이 겹쳐 정작 보려던 한 대가 묻힌다.
기본은 전부이고, 고른 것은 껐다 켜도 남는다. `전체 보기` 로 되돌린다.

고르기는 **그리는 것만** 바꾼다 — 값은 계속 받고 있으므로, 풀면 그동안의 선이
그대로 살아 있다.

### 4.2 하루 누적 — 지난 날도 볼 수 있다

액티브 서비스 오른쪽의 누적 카드에서 **날짜를 고르면 그날 하루**(5분 × 288포인트)를
본다. 장애 다음 날 «어제 이 시간엔 어땠나» 를 묻는 자리다. `오늘` 버튼으로 돌아온다.

- 지난 날에는 **방문자 수를 내놓지 않는다.** 콜렉터의 방문자 커맨드에는 날짜가 없어
  오늘 값이 오기 때문이다 — 그날 것으로 읽히면 거짓이 된다
- 지난 날은 값이 더 이상 바뀌지 않으므로 다시 묻지 않는다(오늘만 1분마다 갱신)

## 7. 설정 (⚙)

**데이터 디렉토리** — 설정 파일(`config.json`)과 로그 파일이 있는 곳. 현재 경로를 보여준다.

**SQL 바인딩 파라미터** — 프로파일의 SQL 은 값 대신 `?` 로 온다.

| 선택 | 결과 |
|---|---|
| 문장에 채워서 보기 (기본) | `where id=126` — 그대로 복사해 DB 에 붙일 수 있다 |
| 값을 따로 보기 | `where id=?` · 바인딩 `126` |

**단축키** — 목록을 그대로 보여준다.

**마지막 접속 정보** — 읽기 전용.

### 7.1 저장되는 것

껐다 켜도 그대로다. **바뀔 때마다** 남긴다 — 앱이 죽으면 «끌 때» 는 오지 않는다.

| 저장됨 | 저장 안 됨 |
|---|---|
| 패널 크기 (서비스 목록 · 상세 · 트랜잭션 표) | 검색 필터(서비스 포함 · IP) |
| 마지막에 보던 탭 (XLog / Counter / Alert) | 열어 둔 상세 탭 |
| 차트 설정 (Y축 · 범위 · Y 최대 · 무시 구간) | 고른 구간 |
| 글자 크기 · 언어 · SQL 바인딩 표시 | |

**필터를 저장하지 않는 이유:** 어제 걸어 둔 필터를 잊고 켜면 «왜 아무것도 안 보이지» 가 된다.
빈 화면과 «필터에 걸려 0건» 은 눈으로 구별이 안 된다.

---

### 7.2 껐다 켜도 남는 것

배치·차트 설정에 더해 **조회 조건**이 남는다 — 응답시간·에러만·고른 오브젝트·
서비스·IP 필터, 실시간/과거 모드, 카운터에서 고른 서버.

**과거 구간(시작·끝 시각)은 남기지 않는다.** 어제 보던 «최근 1시간» 은 오늘 열면
남의 시간이고, 켜자마자 옛날 구간을 받아 오면 지금이 안 보인다.
열어 둔 상세 탭도 아직 복원하지 않는다.

### 7.3 XLog 버퍼 상한

차트가 들고 있을 **최대 건수**다. 창(범위) 밖은 시간으로 지우고, 그래도 남는 것이
많으면 이 수에서 **오래된 점부터** 버린다.

| 고를 수 있는 값 | 대략 메모리 |
|---:|---:|
| **100,000**(기본) | 약 37MB |
| 300,000 | 약 111MB |
| 500,000 | 약 186MB |
| 1,000,000 | 약 371MB |

범위를 30분으로 두고 트래픽이 많으면 기본값이 먼저 걸린다 — 그때는 차트 아래에
«버퍼 상한 … 오래된 점부터 지웁니다» 가 뜬다. **뜨면 둘 중 하나다:** 범위를 좁히거나
이 값을 올린다. 올리면 그만큼 메모리를 쓴다.

바꾸면 열려 있는 화면에 바로 적용되고, **이미 받아 둔 점은 그대로 남는다.**

### 7.4 «점이 사라진다» 싶을 때

차트 오른쪽 위에 «데이터 시각이 이 PC 보다 N초 앞섭니다/뒤처집니다» 가 뜨면
**시계가 어긋난 것이다.** 차트의 오른쪽 끝은 이 PC 의 «지금» 이라, 그만큼 앞선 점은
창 밖에 놓이고 뒤처지면 오른쪽이 빈 채로 남는다. 스트림은 멀쩡하다.
콜렉터·에이전트 서버와 이 PC 의 시각을 맞추면 사라진다.

배지가 안 뜨는데도 비어 보이면 시계 문제가 아니다. 그때는 **버퍼 상한(7.3)** 과
범위(1·5·10·30분), 필터를 함께 확인한다.

## 8. 단축키

입력칸에 글자를 치는 중에는 동작하지 않는다 — 서비스 이름에 `1` 을 치는데 탭이 바뀌면 안 된다.
`Esc` 만 살아 있고, 그건 «이 칸에서 빠져나온다» 는 뜻이다.

| 키 | 하는 일 |
|---|---|
| `Esc` | 보고 있는 상세 닫기 |
| `Ctrl+F` | 프로파일 검색으로 이동 (XLog 탭으로 데려간다) |
| `Ctrl+1` / `Ctrl+2` / `Ctrl+3` | XLog / Counter / Alert 탭 |
| `Ctrl+W` | 상세 탭 닫기 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 다음 / 이전 상세 탭 |
| `Ctrl+,` | 설정 열기 |
| `Ctrl+R` | 실시간 ↔ 과거 |
| `F5` | 다시 조회 (과거 구간에서만) |

mac 에서는 `Ctrl` 자리에 `Cmd` 도 통한다.

## 9. 이럴 땐

| 증상 | 까닭 / 할 일 |
|---|---|
| 상세를 열었는데 `호출 흐름` 이 없다 | 그 요청은 한 앱에서 끝났다(GxID 가 없다). 흐름으로 그릴 게 없다 |
| 이름 대신 `0x1a2b3c` 같은 값이 보인다 | 이름 사전이 아직 안 올라왔다. `텍스트 캐시 비우기` 후 다음 전송을 기다린다 |
| 토폴로지가 비어 있다 | 에이전트의 인터랙션 수집이 꺼져 있다 (4장 참고) |
| 프로파일 검색이 0건인데 분명히 있다 | 검색 대상은 **드래그로 고른 구간**이다. 구간을 다시 잡고 검색한다 |
| 과거 조회 버튼이 안 눌린다 | 버튼 옆에 막힌 이유가 나온다 — 끝 시각이 시작보다 앞이거나, 시작이 미래이거나, 구간이 6시간을 넘거나, 하루를 넘어가는 경우 |
